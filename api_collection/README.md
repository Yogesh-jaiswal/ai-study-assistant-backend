# API Collection

Insomnia collection for the **AI Study Assistant Backend**.

This collection provides a convenient way to explore, test, and develop against the backend API. The API supports an educational AI platform for working with study materials, generating learning content, and evaluating student performance.

---

## What the API Provides

The backend currently supports three main areas:

* **Study Material Management** — notebooks, uploads, document processing, and generated content.
* **AI-Powered Learning** — summaries, quizzes, exams, mind maps, and other educational content generated from study materials.
* **Assessment & Evaluation** — exam attempts, answer evaluation, scoring, and related assessment workflows.

The collection is intended for both developers consuming the API and contributors working on the backend.

---

## Collection Structure

Requests are organized into folders based on the API's route structure and functionality.

This keeps related endpoints together and makes it easier to navigate the collection without duplicating the complete API documentation.

For detailed endpoint specifications, request/response schemas, and API behavior, refer to the project's [API documentation](../docs/api/Infrastructure.md).

## Environment Variables

The collection uses environment variables for values that change between requests or environments.

| Variable           | Purpose                                          |
| ------------------ | ------------------------------------------------ |
| `host_url`         | Base URL of the running API                      |
| `access_token`     | Authentication token used by protected endpoints |
| `access_token_exp` | Access-token expiration timestamp                |
| `notebook_id`      | ID of the notebook being used during testing     |
| `upload_id`        | ID of an uploaded resource                       |
| `content_id`       | ID of generated or stored content                |
| `evaluation_id`    | ID of an evaluation resource                     |
| `limit`            | Limit for the listing APIs                       |
| `page`             | Page number for the listing APIs                 |

Some IDs are produced by earlier requests and can then be reused by subsequent requests.

## Getting Started

### 1. Start the API

Run the backend locally using the project's normal development setup.

The default local host used by this collection is:

```text
http://localhost:5000
```

Update `host_url` if the API is running elsewhere.

### 2. Configure the Environment

Create or select the appropriate environment in your API client and provide the required values.

At minimum, protected endpoints require a valid `access_token`.

Resource IDs such as `notebook_id`, `upload_id`, `content_id`, and `evaluation_id` should be populated with IDs from the resources being tested.

### 3. Run Requests

Requests can be executed individually while developing or debugging a particular feature.

For workflows with dependent resources, execute the relevant requests in their expected order so that IDs generated by earlier operations are available to later requests.

## Using the Collection

The API collection is available in two export formats:

* **Insomnia V5 (YAML)** — recommended for users working with [Insomnia](https://insomnia.rest/). This format preserves the collection structure and Insomnia-specific environment configuration.
* **HAR (`.har`)** — recommended for users who do not have Insomnia. HAR is a standard HTTP Archive format that can be imported into API clients such as Postman to create requests for testing.

### Using Insomnia

Import the **Insomnia V5 YAML** collection into Insomnia and configure the required environment variables before running requests.

### Using Postman or Another API Client

If you do not use Insomnia, import the **HAR file** into Postman or another API client that supports HAR imports.

The HAR export contains the HTTP request information needed to recreate and test the API requests. However, Insomnia-specific features such as environments, variables, and collection configuration may not be preserved when using the HAR format.

After importing the HAR file, configure the required environment values in your API client. In particular, set:

* `host_url` — the base URL of the running API.
* `access_token` — a valid authentication token for protected endpoints.
* Resource IDs such as `notebook_id`, `upload_id`, `content_id`, and `evaluation_id` as required by the workflow being tested.

For the best experience and full collection structure, use the **Insomnia V5 YAML** format when Insomnia is available. Use the **HAR** export as an alternative for users who prefer Postman or another compatible API client.

## Authentication

Most application endpoints require authentication.

Set the `access_token` environment variable to a valid token before making authenticated requests.

Do not commit real access tokens or other secrets to the repository.

## Contributing

If you are contributing to the backend:

1. Start the development environment.
2. Import or update the collection.
3. Configure the required environment variables.
4. Test the affected workflow.
5. Verify that existing workflows still behave correctly.
6. Update the API documentation when an endpoint's public behavior changes.

When adding new endpoints, keep the collection organization consistent with the backend's route structure.

## Notes

This collection is primarily intended for local development, manual testing, integration testing, and contributor workflows.

Keep environment-specific values and secrets in Insomnia environments rather than committing them directly to requests.
